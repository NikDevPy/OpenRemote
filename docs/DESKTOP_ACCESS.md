# OpenRemote: графическая сессия Ubuntu GNOME / Wayland

Графические команды доступны только для **явно разрешённого владельцем устройства**
сеанса. OpenRemote не обходит GNOME, не использует root, uinput или X11-injection.

## Поддержка

- Linux / GNOME / Wayland, один монитор на первом этапе.
- Python агента может находиться в виртуальном окружении. Отдельный локальный
  помощник запускается через системный `/usr/bin/python3` и использует пакетные
  `python3-dbus`, `python3-gi` и GStreamer/PipeWire.
- Дисплей и session bus берутся только из процессов **того же пользователя**.
- В приватной пользовательской директории `/run/user/$UID` создаётся сокет
  `openremote-desktop.sock` с правами `0600`; порт в сети не открывается.
- Окончательное разрешение выдаёт **сам GNOME** через стандартный диалог
  демонстрации экрана и управления. Без него чтение экрана и инъекция ввода
  невозможны.
- При простое более 15 минут соединение завершается. Можно закрыть вручную.

## Установка системных библиотек (Ubuntu)

```bash
sudo apt install python3-dbus python3-gi gir1.2-gstreamer-1.0 \
  gstreamer1.0-pipewire gstreamer1.0-plugins-good
```

Обновите пакет OpenRemote. Затем **локально на устройстве** добавьте в его
приватный `~/.config/openremote-agent/<device>.json`:

```json
"desktop_enabled": true,
"desktop_input_enabled": true
```

Первое разрешает экран, второе дополнительно позволяет ввод. Если нужен
только обзор, установите `desktop_input_enabled: false`. Оба флага по
умолчанию **false**. Требуется роль `admin`; глобального включения у
подключённых SSH-узлов нет. Каждый удалённый агент проверяет собственный
конфиг и системное разрешение.

Перезапустите только соответствующий OpenRemote gateway/tunnel после
обновления кода/конфига, затем обновите схему доступных инструментов в
подключённом плагине ChatGPT.

## Рабочий процесс

1. `desktop_status(device_id="terra")` проверяет состояние и разрешённые уровни.
2. `desktop_connect(device_id="terra")` вызывает GNOME-диалог. Пользователь
   выбирает экран и подтверждает разрешения на локальном дисплее.
3. `desktop_screenshot(max_width=1280)` получает JPEG через PipeWire.
   Возвращаемый base64 содержит **реальные пиксели рабочего стола** и может
   включать пароли, личные документы и уведомления. Не сохраняйте его в Git.
4. `desktop_click(x,y,button="left")` использует координаты **последнего
   скриншота**, с автоматическим пересчётом масштаба в физический размер.
5. `desktop_move(x,y)` проверяет hover; `desktop_drag(x,y,to_x,to_y)`
   выполняет перетаскивание; `desktop_scroll(x,y,steps)` прокручивает карту.
6. `desktop_key(name="escape")` и `desktop_type_text(text="...")` отправляют
   ограниченные клавиши и текст. Максимальная длина текста 256 символов.
7. `desktop_disconnect()` закрывает портал и сбрасывает доступ.

Портал разрешает конкретный пользовательский экран, а не доступ к системным
паролям. OpenRemote не должен обходить системный запрос согласия. Если
пользователь отказал или GNOME не предоставляет поток, инструмент возвращает
ошибку вместо альтернативного обходного захвата.

## Ограничения и диагностика

- Wayland GNOME может отказать любому внешнему захвату через
  `org.gnome.Shell.Screenshot`: это ожидаемая защита, использовать только
  `org.freedesktop.portal.RemoteDesktop` и `ScreenCast`.
- Предоставление доступа зависит от активной разблокированной графической
  сессии. SSH-доступ или успешный UI Playwright **не равен** разрешению GNOME.
- Поток PipeWire требует `pipewiresrc`, `jpegenc`, GStreamer GI и
  разрешения портала. Тесты с mock-интерфейсами не заменяют реальную проверку
  после разрешения пользователем.
- При двух дисплеях нужно расширить выбор потока; сейчас используется первый.
- Закрытие процессов пользователя вне OpenRemote не требуется и не выполняется.
- Разрешение на экран может быть отозвано в системном индикаторе GNOME или
  вызовом `desktop_disconnect`.
