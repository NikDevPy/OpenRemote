# Протокол end-to-end проверки

Результат любого сценария по умолчанию — **НЕ ВЫПОЛНЕН**, пока нет доказательства.
Заполнять для Plus A и независимо для Plus B. Не записывать токены/персональные
данные и не публиковать raw conversation JSON без проверки.

Записать: дату, тариф из настроек, web/desktop/mobile, Chat/Work, модель,
личный/workspace, версию стенда/commit, tunnel или HTTPS, auth method,
инструменты после discovery, точный текст ошибки и запрошенные подтверждения.

| № | Действие | Критерий |
|---|---|---|
| 1 | Добавить собственный неопубликованный MCP | Есть созданный плагин; тариф не блокирует подключение |
| 2 | Посмотреть инструменты | system_info, list_files, execute_command; верные schemas и annotations |
| 3 | В обычном «Чат»: «Используй OpenRemote Probe.system_info» | Реальный tool result с os/machine/operation_id |
| 4 | «Используй OpenRemote Probe.list_files для path='.'» | Только имена тестового каталога |
| 5 | Новый случайный nonce, echo_probe | Реальный subprocess PID, nonce и SHA-256 совпадают |
| 6 | Новый nonce, write_probe | Подтверждение клиента зафиксировано; exit_code=0; файл существует на хосте |
| 7 | list_files после write_probe | Видно имя receipt; содержимое локально соответствует nonce и SHA-256 |
| 8 | Отклонить write-вызов в новом чате, если клиент показывает подтверждение | Файл не появился; не повторять автоматически |
| 9 | list_files с ../ и symlink наружу | Отказ сервера; чужих данных нет |
| 10 | execute_command с произвольным sh/rm | Отказ схемы/политики; ничего не запускалось |
| 11 | Остановить tunnel-client | Недоступность; не изображать успешный вызов |
| 12 | Перезапустить tunnel-client | Новый безопасный вызов работает |
| 13 | Отозвать доступ/отвязать туннель штатными средствами Platform | Новые вызовы перестают работать |
| 14 | Plus B самостоятельно добавляет свой MCP | Повторены 1–7 в обычном «Чат» |
| 15 | Если доступно частное sharing: передать плагин Plus B | Установка, своя авторизация и изоляция устройств проверены |
| 16 | Публичная заявка | Отдельно: scan, review, решение и условия публикации; не заменять пунктом 1 |

Пример положительного вызова: `execute_command(command="write_probe",
nonce="plusA_20261107_unique01")`. Для повторного опыта менять nonce.
Проверить на хосте только собственный `.receipt`, не реальные пользовательские
файлы. Сохранить подтверждённый результат и SHA-256 в отдельном отчёте.

**Успех 1–7 подтверждает только ограниченный write-инструмент и запуск
фиксированной программы в этом аккаунте и режиме.** Для терминала общего
назначения нужны отдельная политика, изоляция и испытания. Нельзя скрывать
поведение под readOnlyHint или переименовывать инструмент ради обхода отказа.

Условие перехода к основной разработке: пункты 1–7 на Plus A и B, понятный
маршрут распространения, подтверждённые ограничения и принятое решение
по Direct/Broker. До этого финальная архитектура остаётся открытой.
