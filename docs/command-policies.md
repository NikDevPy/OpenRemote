# Командные политики OpenRemote (личный MVP)

OpenRemote разрешает некоторые действия, на которые RDC накладывает дополнительный запрет по имени команды. **Это не разрешение обходить безопасность ChatGPT.** Конкретный инструмент может быть недоступен, потребовать подтверждения или быть отклонён клиентом или правилами платформы.

## Модель

В OpenRemote команда определяется **локально**, по точному `command_id`:

- `standard`: фиксированный `argv`, запуск только для operator/admin; никакого shell, argv, адреса или пути от MCP-пользователя. Пример: `python-version`.
- `privileged`: фиксированный `argv`, право admin на целевом устройстве, **разовое интерактивное разрешение на самом устройстве**, срок 1–300 секунд. Применяется к `sudo`, `mount`, `umount`, `dd`, `fdisk`, `iptables`, `shutdown`, `reboot`, `systemctl`, shell и другим чувствительным исполняемым файлам.
- `preview_command`: read-only инструмент, показывает описание действия, риск, требуемую роль и состояние локального разрешения. Не выдаёт аргументы или секреты.
- `execute_command`: write с `destructiveHint=true` и `openWorldHint=true`: разрешённая команда **может** менять систему или обращаться к сети. По умолчанию клиент ChatGPT может требовать подтверждения write.

Две независимые проверки выполняются при SSH-маршрутизации: локальная роль terra и политика/роль целевого узла rock. `role=admin` в текущем MVP принадлежит **всему MCP-серверу**, а не отдельному пользователю. Это не многоарендная система.

## Пример привилегированной команды (не включён в рабочий конфиг)

В локальном JSON целевого устройства:

```json
{
  "role": "admin",
  "commands": {
    "sudo-identity": {
      "argv": ["/usr/bin/sudo", "-n", "/usr/bin/id"],
      "risk": "privileged",
      "summary": "Запуск id через заранее ограниченное sudoers",
      "timeout": 5
    }
  }
}
```

Это иллюстрация. Никакой `sudoers` здесь автоматически не создаётся. Если ОС запрещает эту команду или требует пароль, OpenRemote не обходит решение ОС. **Не включать широкое NOPASSWD: ALL.** При настройке sudoers выдавать право только на явно необходимые программы и точные аргументы.

Процедура:

1. Сначала ChatGPT вызывает `preview_command(command_id="sudo-identity", device_id="rock")`.
2. Владелец **сам** открывает интерактивный локальный терминал целевого устройства и выполняет:

   ```bash
   /path/to/.venv/bin/python -m openremote_agent.server \
     --config /path/to/private-config.json \
     --approve-command sudo-identity --approve-ttl 120
   ```

3. Программа показывает точные аргументы из локального конфига и просит ввести `APPROVE sudo-identity`. Неинтерактивный stdin отвергается. Разрешение хранится в локальной SQLite, привязывается к SHA-256 отпечатку конкретных argv, таймаута, риска, устройства и sandbox, и погашается **до запуска** команды. Изменение политики аннулирует старое разрешение. Повторное исполнение без нового допуска не работает.
4. Клиент ChatGPT отдельно применяет своё подтверждение write-инструмента, после чего агент повторно проверяет роль/политику и одноразовый допуск.

CLI-разрешение **не является криптографическим доказательством присутствия человека** (например, обладатель доступной интерактивной PTY-сессии может вводить текст). Поэтому перед публичным выпуском нужны device-side подтверждение через доверенный UI/OS и отдельная идентификация каждого пользователя. Не пытаться запускать процедуру разрешения моделью через другой инструмент вместо владельца.

## Что блокируется всегда

- Произвольная команда или shell из MCP-параметров, динамические аргументы без описанной политики.
- Наличие `risk=standard` для типовых чувствительных бинарников.
- `sudo` без флага `-n` (интерактивного запроса пароля не будет).
- Привилегированная команда без роли admin или без локального неиспользованного допуска.
- Любое действие, которое запрещено ChatGPT, правами ОС или политикой устройства.

## Технические ограничения

Аудит записывает название инструмента и исход без полного argv, содержимого, stdout или токенов. Одноразовые разрешения сохраняются между перезапусками в SQLite. Максимальное время команды 60 секунд, вывода 8 КиБ на поток. `stdin=DEVNULL`, процесс без `shell=True`, новая группа процессов с ограниченным таймаутом.

**Это управляемый личный прототип, не публичный плагин с подтверждённым разрешением на любой shell.** Публичный review может потребовать отдельные MCP-инструменты с конкретными схемами для каждой административной операции; универсальный исполнитель нельзя маскировать под список безвредных инструментов.
