# OpenRemote v0.4.0 — development release notes

**Status:** tested on Linux; not yet published as a GitHub Release.
**License:** MIT.

## New capabilities

- Persistent non-interactive process jobs that continue running after the
  initiating MCP stdio/SSH request closes.
- Job status, output pagination, cancellation, history and log cleanup.
- Linux pidfd-based cancellation to avoid recycled-PID termination.
- Per-device limits: up to 8 active jobs, 250 stored jobs; maximum job
  duration 6 hours; up to 8 MiB stdout and stderr each.
- Resumable binary uploads and downloads in trusted workspaces, with exact
  offsets, base64 chunks (up to 128 KiB), final SHA-256 checks and atomic
  target creation/replacement.
- Binary files up to 1 GiB; pending upload sessions expire after 24 hours.
- Existing tool behavior and terra-to-rock SSH/Tailscale routing retained.

## Confirmed

- Automated test suite on Linux x86_64.
- Real staged MCP integration between Linux terra (x86_64) and rock (ARM64),
  including a job surviving SSH disconnect, cancellation, stdout recovery,
  and binary file integrity after upload/download.
- **Windows: not tested, not supported.**
- **macOS: not tested, not supported.**

## Not implemented yet

- Interactive PTY sessions and writable terminal stdin.
- Jobs automatically restarting after power loss or reboot.
- Streaming binary transfers directly between remote machines without
  routing chunks through ChatGPT.
- Separate authenticated users/RBAC per plugin caller.
- Windows and macOS agent support.

Start with [JOBS](../JOBS.md), [TRANSFERS](../TRANSFERS.md) and
[SECURITY](../SECURITY.md). This is an early-stage personal remote
administration tool; test its capabilities before using on critical systems.
