# OpenRemote v0.5.0 — Linux preview (development notes)

**Status:** prepared and tested on Linux; no public GitHub Release is implied
by this document. **License:** MIT.

## New in v0.5.0

- **Parallel-chat safety:** database WAL and serialized schema initialization,
  cross-process advisory locks for writes to the same workspace path, and
  a shared four-slot direct-command admission limit.
- **Background job deduplication:** optional human-readable `task_label`
  and caller-chosen `idempotency_key`. Retrying the same operation returns
  the same job instead of executing a duplicate.
- **Deterministic overload handling:** eight active background jobs per target,
  250 stored job entries, existing 8 MiB output caps retained.
- **Optional Linux GUI:** lightweight PySide6 Control Center with device view,
  on-demand SSH peer diagnostics, activity, transfers, preferences, dark mode
  and supported-desktop tray behavior.
- **Single GUI instance**, no repeated MCP sessions or constant SSH polling
  from the dashboard.
- **Regression tests and benchmarks** for simultaneous clients, conflicts,
  background admission and Qt offscreen rendering.

## Evidence

On the Linux x86_64 development gateway, 12 concurrent read-only agent
instances passed after fixing SQLite initialization races; eight simultaneous
writes to the same file resulted in exactly one commit. The test also checked
that no more than eight background jobs were admitted concurrently.

Independent MCP stdio benchmark on the development gateway:
- 8 concurrent clients × 3 read-only calls = 24 successful calls, 0.803 s
  total wall clock (max one child RSS: 62.6 MiB).
- 4 concurrent clients targeting Linux ARM64 over SSH × 3 calls =
  12 successful calls, 5.769 s total wall clock.

This benchmark **does not** test hosted OpenAI Tunnel throughput, multi-user
identity, physical Linux tray behavior or performance on every system.

PySide6 Qt GUI successfully rendered a 1050×720 screenshot using the
offscreen platform. Qt tray behavior depends on the desktop environment. A real GNOME Wayland
session confirmed the tray icon remained visible after the GUI window was
closed/hidden. Other Linux desktops remain unverified.

## Remaining limitations

- No automatic authenticated per-chat identity. Labels/keys are only
  voluntary organizational metadata, not an access-control system.
- No guarantee of isolation against direct shell commands, unrelated
  filesystem processes or malicious content. Advisory locks apply to
  cooperating OpenRemote file operations.
- No interactive PTY input/resize yet; persistent **non-interactive** jobs
  are available.
- Secure MCP Tunnel imposes OpenAI's independent limits and permission
  requirements.
- No tested Windows or macOS agents, builds, or desktop GUI.
- Remote MCP calls over SSH still incur process-startup overhead.
