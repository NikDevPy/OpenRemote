# OpenRemote v0.6.0 — graphical Linux onboarding preview

**Status:** Linux amd64 early-access installer, not a stable cross-platform
release. **License:** MIT.

## First-run experience

The user installs a .deb package from a verified distribution source, opens
OpenRemote from the Linux application menu, and follows a six-step Qt wizard:

1. Welcome with a visual gateway → Secure MCP Tunnel → ChatGPT diagram.
2. Create or sign in to an OpenAI account in the official browser.
3. Create and associate a private MCP tunnel in Platform settings.
4. Enter the Tunnel ID and a restricted runtime API key; select the official
   tunnel-client binary downloaded separately from OpenAI GitHub releases.
5. Configure and verify the local agent; install an owner-only user systemd
   service using tunnel-client and a private runtime key file.
6. Open ChatGPT Plugins and create a private custom MCP server using the tunnel.

No OpenAI account password is requested. The key is masked and never stored
in QSettings, logged, committed, or placed on command lines. Existing
unrelated configs and services are not overwritten. Retries are allowed when
the local key and managed profile match. The agent starts as a viewer with
arbitrary command execution disabled.

## Debian preview build and first-launch behavior

\`scripts/build_linux_deb.sh\` builds a small amd64 .deb containing an
application launcher, real SVG icon, wheel and user-only bootstrap script.
On first launch, the bootstrap creates a versioned per-user Python venv and
installs OpenRemote, PySide6 and agent dependencies from PyPI. It does not
run pip or connect to OpenAI as root during package installation.

This **requires network access on first run** and is not a fully offline
app bundle. On a single x86_64 Linux development host the per-user runtime
occupied approximately 302 MiB. Other Debian/Ubuntu versions and desktop
shells have not been exhaustively validated.

The Linux preview was validated by extracting the .deb into an isolated
test directory, running its actual launcher with a temporary home,
installing the dependencies, and rendering an actual onboarding screenshot
with Qt offscreen. The official tunnel-client flow was tested using a
mock binary in a temporary directory, not a fresh production OpenAI account.
Do not describe the hosted onboarding as verified end to end until the
user completes it using their own account.

## Desktop and UI improvements

- Russian and English language selection with persistent local preference.
- Light/dark themes with corrected Qt scroll surface backgrounds.
- Real application SVG icon, desktop entry and opt-in GUI autostart.
- Clear online/offline/unknown device statuses and on-demand SSH checks.
- System tray on supported Linux desktop environments.
- Separate background tunnel service unaffected by quitting the GUI.

## Unchanged core guarantees and limitations

- Multi-chat concurrency is protected by shared OS locks, bounded command
  admission and idempotency keys for background jobs.
- The agent and tunnel still have all Linux/ChatGPT/Platform limits documented
  in [SECURITY](../SECURITY.md), [MULTI_CHAT](../MULTI_CHAT.md).
- Windows .exe and macOS packages **do not exist as supported releases**.
  Native agent process/filesystem security and actual platform testing
  are required before publishing them.
