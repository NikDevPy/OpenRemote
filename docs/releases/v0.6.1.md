# OpenRemote v0.6.1 — Linux desktop hotfix (preview)

This is a small corrective release for the Linux-only OpenRemote GUI and first-run experience. The existing MCP agent, runtime credentials, SSH peers and systemd tunnel services are unchanged.

## Fixed

- The Russian **Secure Tunnel** label now fits inside its infographic. All three captions are measured against the available card width and scale down only when necessary. Tested with Russian and English labels at several logical window widths.
- The GUI detects an existing hostname-matched private agent configuration, such as `workstation.json`, instead of always launching onboarding when `agent.json` is absent.
- A private agent configuration supplied with `--config` still takes precedence.
- UI regression tests cover label widths, correct local configuration selection and visible online status badges.

## Tested

- Linux x86_64 / GNOME Wayland. The user-scoped copy extracted from the .deb starts a real Qt application and displays the dashboard without re-entering credentials.
- Existing tunnel service remains active. A registered SSH peer was tested separately through the GUI backend.
- Python unit tests, Qt offscreen screenshots and Linux Debian build were rerun.
- The fresh .deb package still depends on PyPI on its first launch and requires external OpenAI tunnel-client installation for *new* users.
- A user-scoped extraction of the .deb is not a system-wide dpkg installation. System installation requires administrator approval.

## Platform compatibility

Windows .exe and native macOS packages remain **unreleased and untested**. The Linux amd64 package is a preview, not a stable, fully offline release.
