# OpenRemote v0.6.2 — desktop design polish (Linux preview)

This release brings the native Linux Qt Control Center close to the two
approved light Apple-inspired reference screens and fixes visual regressions
that previously made controls difficult to read or operate.

## UI improvements

- Distinct white cards on a soft lavender background with subtle reliable
  shadows, stronger typography, consistent spacing and high-contrast labels.
- Real Qt-painted computer, server, task, transfer, folder, CPU, copy and
  settings icons, replacing platform-dependent symbol glyphs.
- Clearly recognizable purple **Check connection** QPushButton with
  hover/disabled states, not a bare text action.
- Bilingual RU/EN custom-styled language selector instead of a native
  system popup; styled Qt checkboxes and state indicators.
- Reworked Settings layout and connection details, including row heights to
  prevent text clipping and proper column alignment.
- The inner scroll widget no longer overrides the app's card/button
  stylesheet. Old QWidgets are detached immediately during page rerenders,
  avoiding overlay/ghost elements.
- Two-column metric reflow in narrow windows; four functional pages retain
  consistent styles in both themes.

## Validation

- Light UI: all four screens reviewed from genuine Qt captures.
- Dark UI: Devices and Settings reviewed in English.
- Narrow and wide layouts tested with Qt.
- Functional GUI regression tests cover the appearance controls, device
  icons and status, the language menu and responsive metric layout.
- Real agent and tunnel are deliberately separate from the GUI.

Published images use **synthetic demonstration data**, never real private
agent config or runtime credentials. See [DESIGN_QA](../DESIGN_QA.md).

## Installer and supported platforms

The v0.6.2 Linux amd64 `.deb` preview keeps the existing user-scoped
bootstrap strategy: dependencies download on first launch, Qt Essentials
is used to keep the install smaller, and the official OpenAI tunnel-client
remains a separate, user-authorized dependency for new setups.

The GUI upgrade is compatible with existing private device configs,
runtime credentials and SSH peers. It does not require creating new
tunnels or repeating onboarding.

Windows/macOS native packages remain **untested and unsupported**. No
fully verified .exe setup is claimed.
